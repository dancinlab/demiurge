## 2026-06-02 — cloud substrate: `hexa cloud alive` — unreachable-vs-dead disambiguator (hexa-lang PR#2498)

- Shipped `hexa cloud alive <id...> [--provider P] [--json]` (alias `probe`) in `stdlib/cloud/alive.hexa` — queries the PROVIDER API directly (vast.ai + runpod), NOT ssh, reusing the SAME clients + key resolution `rent`/`down` use (d19/d3 — no new HTTP stack, no new key path). Exit codes for script/API consumers: 0=RUNNING · 3=STOPPED · 4=GONE · 255=api/cred; multi-id exit = worst/most-actionable (255>4>3>0). `--json` emits `[{id,provider,state,exit,raw}]`; bare = human table.

API/transport error → UNKNOWN (NOT GONE — a false GONE would tear down real compute). A GONE ruling additionally requires a TRUSTWORTHY not-present signal: if the vast enumeration call fails, a would-be GONE is downgraded to UNKNOWN.
